Controlled Multi-Agent Engine · Execution Flow

How They Actually Flow Together

01 · orchestrator.py Main Agent (Orchestrator)
  • Checks data access permissions
  • Freezes point-in-time snapshot_id
  • Dispatches agent tasks
02 · agents.py DeliverableAgent
  • Single reusable writer
  • Loads Skill + context
  • Calls ModelGateway
03 · agents.py QualityReviewer (checks, verifies)
  • Required template sections are present
  • Section text is present
  • Citations match (snapshot_id)
04 · agents.py KnowledgeSteward
  • Extracts new workshop facts
  • Diffs against KB
  • Flags conflicts for review

Architecture Design · Shared Infrastructure, Separate Classes

  • Same underlying infrastructure:
    • All agents share KnowledgeStore database access, LLM connector, Pydantic validation schemas, and frozen snapshot_id.
  • Three separate classes in agents.py (restricted roles):
    • DeliverableAgent (1 reusable writer instance) loads the matching Skill and drafts content.
    • QualityReviewer independently checks required sections and citations.
    • KnowledgeSteward isolates rule conflicts so nothing auto-overwrites approved decisions.
Pluggable Skill Registry · 1 Skill = 1 Deliverable

Skill Structure

01 · Manifest
  • Skill name, version & purpose
  • Required document sections
  • Selected deterministically by user
02 · Schema
  • Strict JSON output structure
  • Section-by-section layout
  • Required source citation fields
03 · Rules
  • Checks previous steps are done
  • Citations must match snapshot_id
  • Separates workshop notes from KB
Model Gateway · Controlled LLM Abstraction

Model Gateway Structure

01 · Unified Connector
  • Single entry point for all LLM calls
  • Switch AI vendors without changing agents
  • Logs model used, latency & token count
02 · Output & Citation Lock
  • Enforces the Skill JSON schema
  • Allows citations only from snapshot_id
  • Blocks invented source references
03 · Client Data Policy Routing
  • Enterprise Cloud APIs (Claude / OpenAI)
  • On-prem or EU models (Mistral / Local LLM)
  • Routes by project confidentiality level
Layered Project Knowledge Store · Memory & Governance

Knowledge Store Structure

01 · Evidence Store
  • Raw workshop notes & client docs
  • Split into searchable text passages
  • Tagged with role access permissions
02 · Canonical Knowledge
  • Validated rules, decisions & scope
  • Versioned history (v1 to v2)
  • AI updates wait for human approval
03 · Deliverable Store
  • Generated drafts tied to snapshot_id
  • Audit log of reviews & sign-offs
  • Locked client-ready publications
DB: Blob Storage + Vector / Keyword DB
e.g. File storage (S3) + pgvector / Full-Text Search (FTS5)
DB: Relational SQL Tables (ACID)
e.g. PostgreSQL / SQLite (Atomicity, Consistency, Isolation, Durability)
DB: JSON Store + Append-Only SQL
e.g. JSONB + immutable audit log
End-to-End Request, Execution & Approval

Event & Logic Sequence (Steps 1 to 6)

Architecture Blocks: Consultant Workspace Multi-Agent Engine Skill Registry Model Gateway Knowledge Store
Step 01 · Consultant → Main Agent Request & Snapshot
  • UI sends POST /api/generate with skill ID
  • Checks data access permissions
  • Freezes point-in-time snapshot_id
Step 02 · DeliverableAgent → Skills Skill Lookup & Gates
  • Matches requested skill in registry.py
  • Checks workflow phase allows Skill
  • Loads manifest.json (sections, rules)
Step 03 · DeliverableAgent → Knowledge Authorized Context
  • Selects scenario refs (ws01, ws04, ws05)
  • Verifies role ACL on each chunk
  • Reads active Canonical KB (v1)
Step 04 · Gateway + Steward LLM Call & Diff
  • Locks DraftPayload schema & ref enum
  • Calls LLM (or deterministic fixture)
  • KnowledgeSteward diffs facts vs KB
Step 05 · QualityReviewer → UI Validate & Audit
  • Checks required sections & text present
  • Verifies citations match snapshot_id
  • Saves draft, logs events, returns to UI
Step 06 · Consultant / Lead → KB Explicit Approval
  • Confirms report or flags rule conflict
  • Domain Lead promotes rule (v1 to v2)
  • Locks release in publications
snapshot_id (e.g. SNAP-8F3A19C4B201) :
  • What?: Like “git commit” ID of the exact documents and KB rules used for a single AI run.
  • Why?: Prevents citing unapproved data and proves which inputs produced every draft.
